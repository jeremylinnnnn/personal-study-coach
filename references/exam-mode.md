# 备考模式

## 选择复习方式

沿用主文件的备考菜单。先从已选文件和现有学习记录识别科目、考试范围和学习进度。需要时给基础选项「几乎没学／学过一部分／大致学完」，时间可选「一小时内／今晚／还有几天／暂不限制」。如果用户已经提供这些信息，直接开始。只做串讲或研判时，可以先用可读材料开展。选择跨科复习总表后再确认各科考试日期、可用时段和固定安排，并复用现有日历和总表。

## 考前突击与知识串讲

考前突击先从考试范围、有来源的高优先级考点和用户基础里选一小组可以实际学完的内容。阅读对应课件、教材和题目，找出本节必需的前置知识，随用随补。如果时间只够一组，优先带用户学完并做一道代表题。说清本轮覆盖哪些内容，以及余下内容适合在有时间时从哪里继续。

知识串讲先给简短的章节脉络，标出哪些概念是前提、哪些公式是推论、哪些方法解决同一类题。课件和考试范围决定覆盖内容，教材补齐推导。用户没学过的部分按首次学习的深度讲，已经掌握的部分用短例或对比带过。

逐个讲透当前知识点。先用白话说它解决什么问题，再讲定义、符号、成立条件和推导中容易跳过的一步。接着解一道代表题，交代看到哪些条件时能用这个方法、怎样开始、每一步依据和常见失分点。优先用用户已有的练习或历年题，并注明题号或文件位置。需要补充例题时标为自编。最后留一道改条件、问法或情景的短自测，等用户作答后批改。串讲较长时分小节或按模块推进。

## 从练习和试卷研判考点

1. 先读最新的考试范围、考试通知和老师明确强调的材料，核对考试学期、适用范围与题型。标出本次明确覆盖和排除的内容。
2. 阅读实际题目，把作业、课堂测验、模拟题和历年卷对应到具体知识点、常见问法和所需解法。按独立试卷统计反复出现的知识点，同时写清读了多少份。重复版本按一份计。作业和测验中的高频单独记，分值只在材料标出时引用。
3. 结合当前范围、老师强调、历年题型和分值判断顺序。当前官方范围优先于旧卷。课内的核心先修知识如果也值得先补，说明它是为了做后面的题。用户作答暴露的弱点单独注明，以便调整个人复习顺序。
4. 给出短表，写清「优先级｜知识点和常见题型｜证据（文件、年份、页码或题号）｜怎么复习」。区分已确认的考试范围、基于题目样本推断的重点、暂时缺少证据的部分。样本太少时照实说明，不估计精确的出题概率。没有历年卷时，可依据考试范围和课程练习给出暂定重点。

同时选择考前突击或串讲时，直接用这份重点清单确定讲解顺序，并在相应知识点下带做代表题。用户随后选择跨科排表时，再把串讲小节、代表题、错题订正和到期卡片拆成可执行任务。

## 共用工作区

所有科目共用一个复习工作区。需要查看或改动总表时，先按技能正文的「全局复习总表登记」读取绝对路径。有效时，使用该表所在目录的 `review-plan.json` 和各科卡库。没有登记时，先查找已知学习目录里的已有总表。首次创建成功或确认已有总表后，写回对应的登记位置。路径失效时先核对原表位置，移动或改名后更新登记。新增科目、改考试日期、换聊天或换模型时继续使用同一表。选择其他备考成果时按需只读已有数据。

- `review-plan.json` 记录考试、每日可用时间、固定占用、各科任务及已完成分钟。
- `复习安排总表.md` 是生成的全科时间表。收到新科目、新的固定安排或完成反馈时，更新 JSON 后重排剩余任务。
- `courses/<科目ID>/cards.jsonl` 保存该科知识卡、反馈和到期日。每科另保留回忆批次和可选的保留率设置。已有课程笔记仍放在原目录。

## 全局排程

确认各科考试日期和可用时段。未知的考试日期可标为待定。用户只给了大致可用时间时，可先用明确标为暂定的预算出一版可调整的计划。

下文用 `python3` 表示 Python 3.9 及以上。Windows 上可用 `py -3 -X utf8` 或已指向 Python 3 的 `python -X utf8`。HTML 卡片按系统时区运行时可省略 `--timezone`。Windows 显式指定 `Asia/Shanghai` 等 IANA 时区且缺少时区数据库时，可用 `py -3 -m pip install tzdata` 补齐。

给各科任务估时，并明确产出，例如「闭卷做两道一维势阱题并订正」或「用一页纸核查角动量的对易关系」。按考试截止日期、任务优先级及卡片到期情况分配共同的可用时间。建议留出缓冲，允许把定时模拟卷标为需要连续时段。最后一轮优先复盘已错题和到期卡片。

- 有具体时段时，先扣除固定占用。所有科目共享剩余空档和每日上限。当天已过去的具体时段可用 `--not-before HH:MM` 跳过。
- 只有时长时，按每日已扣除其他安排的净时长和顺序分配。日表不猜实际起止钟点。
- 默认把考试前一天作为该科最后复习日。已知要在考试当天复习时，先确认确切的考前可用区间。当前脚本按考前日期排程，考试当天的临时轻量复盘单独提示。
- 未能塞进可用时段的任务列在总表末尾。与用户讨论删减、缩短或增加可用时间。考试日期变更或临时请假后，保留已完成记录并从用户指定日期重算。
- 卡片库中处于当前规划范围的每张卡按已保存的到期日纳入一次，逾期卡从起始日可排。用户评分后再读真实新到期日，不提前预测后续评分。卡片会占用当天复习预算。

输入示例。日期及用时按用户实际情况填写，任务的 `earliest` 和 `deadline` 可省略，`priority` 为 1 至 3，1 优先。需要整块完成的任务设置 `split: false`。任务能够拆分时，通过 `completed_minutes` 记录用户实际完成的部分。

```json
{
  "start": "2026-11-30",
  "days": {
    "2026-11-30": {"windows": [["18:30", "22:00"]], "busy": [["19:30", "20:15"]], "minutes": 120},
    "2026-12-01": {"minutes": 150}
  },
  "subjects": [
    {"id": "physics", "name": "物理", "exam_date": "2026-12-05",
     "tasks": [{"title": "根据错题重做两道模型题", "minutes": 50, "priority": 1}]},
    {"id": "math", "name": "数学", "exam_date": null,
     "tasks": [{"title": "限时小卷", "minutes": 75, "split": false}]}
  ]
}
```

运行技能目录的 `python3 scripts/review_plan.py <工作区>/review-plan.json --from YYYY-MM-DD --output <工作区>/复习安排总表.md`。更新前沿用原有日期和用户已确认的占用。每次生成后查看空余与未排任务。沿用用户的表格文件格式偏好。

## HTML 知识卡

知识卡直接呈现一个具体定义、机制、公式及适用条件或易错边界，可以附简例和来源。一次准备好整组正文再开始，默认约 5 张。已有一两张到期卡时直接复习这几张。正式测试题留在独立的练习环节，作答结果作为安排后续练习的依据。

请用户按这次回忆的难易选择 **重来**（没想起来）、**困难**（费力才想起）、**良好**（顺利想起）或**简单**（马上想起）。无需填写掌握百分比。HTML 按钮上方显示预计复习间隔，评分后直接进入下一张。排期以天为单位，最早安排在次日。同一张卡的不同反馈有时会得到相同间隔，仍按实际回忆选择。可在「复习设置」里切换「日常复习」或「加强复习」，从下次评分生效。算法参数分别为 90% 与 95% 的目标保留率。

每张预制卡需要 `knowledge_id`、`title`、陈述式 `content`、`source`，已有卡沿用知识点 ID，也可显式提供卡片 `id`。正文包含公式时，写成浏览器可直接阅读的 Unicode 文本。批次按此方式准备：

```bash
python3 scripts/fsrs_review.py prepare <科目目录>/cards.jsonl --batch <科目目录>/recall/active.json --input <整组卡片.json> --date YYYY-MM-DD
```

如果有未完成组，先用 `batch-next` 恢复同一批次。正式复习优先用 `python3 scripts/recall_server.py --cards <科目目录>/cards.jsonl --batch <科目目录>/recall/active.json --timezone Asia/Shanghai` 打开实际打印的本机 URL，时区按用户实际情况设置。页面会把真实反馈写回该科卡库。无法启动本机页或用户想离线时，追加 `--export-html <文件路径>.html` 生成可双击打开的独立文件。离线反馈保存在该浏览器，可导出 JSON 供后续核对。自动全科排程读取工作区卡库，离线反馈需经核对后才能用于正式排程。对话备用路径在用户反馈后调用 `batch-rate` 直接取下一张，沿用已准备的正文。
